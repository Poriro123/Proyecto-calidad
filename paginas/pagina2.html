Fundamentos de la Calidad del Software

¿Que es la calidad de software?

La calidad del software es el conjunto de características que permiten que un sistema informático cumpla con las necesidades y expectativas del usuario, tanto en su funcionamiento como en su rendimiento, seguridad y facilidad de uso. Un software de calidad no solo “funciona”, sino que lo hace de manera eficiente, confiable y sostenible en el tiempo. El objetivo de la gestión de la calidad es garantizar que el software cumpla con estándares definidos y que su ciclo de vida sea predecible, eficiente y libre de defectos graves.

Confiabilidad

Descripción: La confiabilidad mide la capacidad del software para funcionar correctamente bajo diferentes condiciones sin fallos. Un sistema confiable asegura que las operaciones críticas se completen correctamente incluso en escenarios adversos.

Ejemplo: Un sistema bancario debe realizar transferencias sin errores, incluso bajo alta carga de usuarios.

Caso de uso: Validar que una aplicación de homebanking no pierda transacciones aunque falle la conexión a internet.

Usabilidad

Descripción: La usabilidad evalúa la facilidad con la que un usuario puede aprender a utilizar y operar un sistema. Incluye aspectos como diseño intuitivo, accesibilidad y experiencia del usuario.

Ejemplo: Una app de delivery con interfaz intuitiva.

Caso de uso: Un nuevo usuario puede registrarse y hacer su primer pedido sin necesidad de un manual.

Mantenibilidad

Descripción: La mantenibilidad indica qué tan fácil es corregir, actualizar o mejorar el software sin introducir nuevos errores ni incurrir en altos costos.

Ejemplo: Código modular y documentado en un ERP.

Caso de uso: El equipo puede cambiar la regla de cálculo de impuestos sin afectar otras funciones.

Eficiencia

Descripción: La eficiencia se refiere al uso óptimo de los recursos del sistema, asegurando buen rendimiento y tiempos de respuesta adecuados.

Ejemplo: Una app de transporte que calcula rutas en segundos.

Caso de uso: El sistema de Uber debe responder en tiempo real al buscar autos cercanos.

Portabilidad

Descripción: La portabilidad es la capacidad de que el software funcione en distintos entornos o plataformas sin necesidad de modificaciones importantes.

Ejemplo: Un software de gestión que funciona en Windows, Linux y macOS.

Caso de uso: Una empresa cambia de servidores Windows a Linux sin necesidad de reescribir el sistema.

Métricas de Calidad

Número de defectos encontrados por fase

Descripción: Métrica que mide la cantidad de errores detectados en cada etapa del desarrollo, ayudando a evaluar la efectividad de las pruebas.

Ejemplo: En pruebas unitarias se detectaron 30 errores, y en integración 10.

Caso de uso: Permite saber si los errores se corrigen antes de llegar al cliente.

Cobertura de pruebas

Descripción: Porcentaje de código ejecutado al correr pruebas automatizadas o manuales. Una alta cobertura reduce el riesgo de errores no detectados.

Ejemplo: Un proyecto tiene 85% de cobertura con JUnit.

Caso de uso: Garantizar que la mayoría de los métodos críticos del sistema estén verificados.

Tiempo medio para resolver fallas

Descripción: Promedio del tiempo que tarda un equipo en identificar, diagnosticar y resolver un defecto reportado.

Ejemplo: Un bug reportado se soluciona en promedio en 2 días.

Caso de uso: Medir la eficiencia del equipo de soporte y desarrollo.

Satisfacción del usuario final

Descripción: Mide el grado de conformidad del cliente con el software mediante encuestas, entrevistas o análisis de uso.

Ejemplo: Encuestas de usabilidad en una app educativa.

Caso de uso: Ajustar la interfaz si los usuarios califican la experiencia como “difícil”.

Estándares Internacionales

ISO 9126

Descripción: Definía seis características principales de calidad: funcionalidad, fiabilidad, usabilidad, eficiencia, mantenibilidad y portabilidad.

Ejemplo: Una empresa de software en salud aplica este estándar para garantizar fiabilidad y seguridad.

Caso de uso: Certificar que la historia clínica electrónica cumpla con requisitos de interoperabilidad.

ISO 25000 (SQuaRE)

Descripción: Evolución de ISO 9126 que establece un marco actualizado para evaluar la calidad del software y del proceso de desarrollo.

Ejemplo: Uso en proyectos de gobierno digital.

Caso de uso: Evaluar la calidad de un sistema de gestión tributaria antes de su implementación nacional.

Técnicas de Prueba

Pruebas funcionales

Descripción: Verifican que el software realice correctamente las funciones especificadas en los requisitos.

Ejemplo: Probar que un carrito de compras en e-commerce calcule bien los precios.

Caso de uso: El cliente agrega 3 productos y el sistema muestra el total correcto.

Pruebas no funcionales

Descripción: Evalúan características como rendimiento, seguridad, escalabilidad y usabilidad.

Ejemplo: Test de carga en un portal educativo en época de inscripciones.

Caso de uso: Verificar que soporte 10.000 usuarios simultáneos.

Unitarias

Descripción: Se enfocan en probar pequeños componentes del software, generalmente funciones o métodos.

Ejemplo: Probar un método de cálculo de intereses.

Caso de uso: Asegurar que el módulo de finanzas funciona antes de integrarlo.

Integración

Descripción: Verifican que los diferentes módulos o subsistemas interactúen correctamente entre sí.

Ejemplo: Probar interacción entre el módulo de facturación y el de stock.

Caso de uso: Al facturar un producto, el stock debe descontarse automáticamente.

Sistema

Descripción: Evalúan el comportamiento global del sistema, asegurando que cumpla con los requisitos funcionales y no funcionales.

Ejemplo: Evaluar un sistema completo de turnos médicos.

Caso de uso: Validar que desde la creación del turno hasta el envío del recordatorio por mail funcione.

Aceptación

Descripción: Pruebas realizadas por el cliente o usuario final para validar que el software cumple con sus necesidades reales.

Ejemplo: Cliente prueba un sistema de gestión de clientes (CRM).

Caso de uso: El usuario valida que puede registrar y buscar clientes de acuerdo a sus necesidades.

Caja negra

Descripción: Método de prueba que se centra en entradas y salidas sin conocer la lógica interna del código.

Ejemplo: Probar login con usuario y contraseña.

Caso de uso: No importa el código, solo que la validación sea correcta.

Caja blanca

Descripción: Analiza la lógica interna y la cobertura de código, asegurando que todas las ramas y condiciones se prueben.

Ejemplo: Revisar que un algoritmo de encriptación cumpla su lógica.

Caso de uso: Analizar el flujo interno del código para cubrir todas las ramas.

Ejemplo de uso de Caja negra y Caja blanca

Una prueba de “caja negra” verifica que al ingresar una contraseña incorrecta el sistema muestre un mensaje de error. Una prueba de “caja blanca” revisa si el algoritmo que valida esa contraseña contempla todos los casos posibles.

Exploratorias

Descripción: Pruebas dinámicas realizadas sin guiones predefinidos, basadas en la experiencia y creatividad del tester.

Ejemplo: Un tester navega libremente por un sistema de reservas.

Caso de uso: Descubrir errores no previstos en los casos de prueba formales.

Herramientas de Calidad

Gestión de pruebas (TestRail, Zephyr)

Descripción: Herramientas que permiten planificar, ejecutar y documentar pruebas, facilitando la trazabilidad.

Ejemplo: Registrar casos de prueba para una app bancaria.

Caso de uso: Controlar qué pruebas se ejecutaron, cuáles pasaron y cuáles fallaron.

Seguimiento de defectos (Jira, Bugzilla)

Descripción: Sistemas que permiten registrar, priorizar, asignar y dar seguimiento a los errores detectados en el software.

Ejemplo: Reportar un bug que impide descargar un informe en PDF.

Caso de uso: Asignar el bug a un desarrollador y darle seguimiento hasta su resolución.

Análisis de calidad (SonarQube)

Descripción: Herramientas que miden la calidad del código fuente y detectan vulnerabilidades o malas prácticas.

Ejemplo: Detectar código duplicado en un proyecto Java.

Caso de uso: Prevenir problemas de mantenibilidad y mejorar la calidad del código fuente.
